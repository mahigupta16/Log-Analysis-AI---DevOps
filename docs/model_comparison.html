Isolation Forest Unsupervised Outlier Detection
Machine Learning
Fast and efficient for outlier detection
Works well on high-dimensional tabular data
No label requirement (unsupervised)
Does not capture temporal relationships in logs
Random partitioning can miss structured anomalies
 Moderate
Moderate false positives due to random partitioning of data across log feature space
✖ Not Selected
Our logs contain temporal sequences that require sequence learning. Isolation Forest has no temporal awareness.
⚙️
One-Class SVM Boundary-based Detection
Machine Learning
Detects anomalies using only normal training data
Flexible kernel functions for non-linear boundaries
High computational cost (O(n²) kernel training)
Poor scalability on large log datasets
No temporal/sequential log modeling
 Low (small sets)
Low on small datasets but significantly increases as log data volume grows
✖ Not Selected
High computational cost and limited scalability make it impractical for DevOps log volumes.
🌳
Random Forest Ensemble Classifier
Machine Learning
High accuracy on labeled HDFS block datasets
Easy to train with interpretable feature importance
Ensemble voting reduces individual tree bias
Fast inference time at deployment
Requires labeled anomaly training data (E1–E29 events)
Lacks native sequence/temporal awareness
 Good Control
Ensemble voting across 100+ decision trees gives strong false positive suppression on HDFS block events
✓ Selected
Used for HDFS block-level classification (hdfs_rf_model.pkl). Trained on 29 HDFS event templates (E1–E29) for high-precision block anomaly detection.
🔁
LSTM Recurrent Neural Network
Deep Learning
Learns sequential patterns in time-series log data
Long-range temporal dependency capture via cell state
Requires large amount of labeled training data
Purely supervised — cannot detect unknown anomaly patterns
 Low
Reduces false positives by learning temporal dependencies in training data
✖ Not Selected
We required an unsupervised approach to detect unknown anomalies without needing labeled failure data.
🧠
LSTM Autoencoder Unsupervised Deep Learning
Deep Learning
Learns normal log behavior without anomaly labels
Captures temporal dependencies via encoder-decoder LSTM
Detects unknown/novel anomalies via reconstruction error
Flexible thresholding for adaptive sensitivity
Higher training time vs. traditional ML models
Requires PyTorch runtime environment
 Very Low
Reconstruction-error thresholding + hybrid keyword heuristic provides precise anomaly flagging
✓ Primary Model
Primary anomaly detection model. Performs unsupervised detection — ideal for sequential log analysis without requiring labeled failure data (lstm_model.pt).
🤖
LogBERT Transformer-based Model
Deep Learning
Learns contextual relationships across full log sequences
Achieves state-of-the-art accuracy on benchmark log datasets
Bidirectional attention captures rich log semantics
Requires large pretraining datasets for convergence
High GPU memory and compute requirements
Longer training and inference time
Complex fine-tuning pipeline
 Very Low
Very low false positives due to deep contextual understanding of full log token sequences
✖ Not Selected
Higher computational cost and complexity exceeds the infrastructure constraints of this DevOps deployment.
💡
Implementation Note: The selected models are managed by ModelManager in services/model_manager.py. The active model is persisted in models/model_config.json and can be switched at runtime via POST /model/set-model. The LSTM Autoencoder uses a hybrid detection rule: anomaly flagged if reconstruction error exceeds the trained threshold or if error keyword count > 0, giving both statistical and heuristic coverage.
